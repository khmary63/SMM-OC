# Video Render Worker

FFmpeg-воркер детерминированной сборки коротких роликов.

Два режима:

* **рилс** — заголовок поверх готовой видео-подложки на всю её длину
  (`POST /render/reel`, процесс «9. Instagram Reels Daily»);
* **слайдшоу** — вертикальный ролик из изображений (`POST /render`,
  WF-CONTENT-003).

## API

| Method | Path | Описание |
|---|---|---|
| GET | `/health` | статус |
| POST | `/upload` | тело запроса — байты подложки → `{source_id}` (201) |
| POST | `/render/reel` | manifest рилса → `{job_id, status}` (202) |
| POST | `/render` | manifest слайдшоу → `{job_id, status}` (202) |
| GET | `/render/:job_id` | статус рендера |
| GET | `/files/:job_id/output.mp4` | готовый ролик (с Bearer) |
| GET | `/public/:job_id/:token/output.mp4` | готовый ролик без Bearer |

Все запросы, кроме `/health` и `/public/...`, — с заголовком
`Authorization: Bearer $VIDEO_RENDER_TOKEN`.

### Почему две отдачи файла

Instagram забирает видео по `video_url` собственным загрузчиком и наши
заголовки не передаёт, поэтому ссылка для него должна открываться без
авторизации. `/public/...` содержит одноразовый токен задачи: ссылку нельзя
угадать, но и Bearer для неё не нужен. Токен возвращается только внутри
`public_url`, в статусе задачи его нет.

Чтобы эта ссылка работала, `VIDEO_PUBLIC_URL` должен быть адресом, видимым
из интернета (не `localhost`). Без переменной рендер отработает, но
`public_url` в ответе не будет — останется только отдача с Bearer.

## Manifest рилса

```json
{
  "source_id": "из POST /upload",
  "text": "I QUIT my job and made $9,000 in 30 days",
  "max_seconds": 60
}
```

Вместо `source_id` можно передать `video_url` (плюс, если нужно,
`video_headers`) — но подложки лежат в Google Drive, а он отдаёт файл
только по токену. Поэтому n8n скачивает подложку своим Drive-креденшлом и
кладёт её в воркер через `/upload`: доступы к Drive остаются в n8n.

Что делает рендер:

* приводит подложку к 1080×1920 обрезкой по центру (не полями: рилс с
  чёрными полосами читается как чужой репост);
* переносит заголовок по словам и подбирает кегль под самую длинную строку;
* рисует его в верхней трети кадра — снизу Instagram кладёт подпись, аватар
  и кнопки;
* держит заголовок весь ролик, с плашкой и обводкой, чтобы он читался и на
  светлой подложке;
* обрезает подложку до `max_seconds` (по умолчанию 60) и требует минимум
  3 секунды — короче Instagram не принимает;
* добавляет тишину, если у подложки нет звуковой дорожки;
* пишет H.264/AAC с `+faststart`.

Ответ `GET /render/:job_id` после успеха:

```json
{
  "status": "succeeded",
  "duration": 12,
  "public_url": "https://.../public/<job>/<token>/output.mp4",
  "public_cover_url": "https://.../public/<job>/<token>/thumbnail.jpg"
}
```

`public_url` идёт прямо в `video_url` публикации рилса.

## Чего воркер не делает

Музыку из библиотеки Instagram наложить нельзя ни здесь, ни где-либо ещё:
Content Publishing API не принимает трек, а лицензированное аудио
добавляется только в приложении. Ролик выходит со звуком подложки.
