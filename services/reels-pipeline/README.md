# Reels Pipeline

Ежедневная подготовка Reels для Instagram: отбор вирусного хука → текст поста →
перевод → подложка → рендер заголовка → доставка в Telegram.

Все шаги соединены в один проход: `node bin/run.js` — один готовый рилс в боте.

```text
YouTube (тренды за 24 ч) ──> отбор одного хука
                                 │
        Drive: базы знаний ──────┼──> тексты: заголовок, надпись, пост, перевод
        Drive: подложка ─────────┤
                                 └──> video-worker: надпись поверх видео
                                          └──> Telegram: видео + готовые тексты
```

**Почему финал в Telegram, а не автопостинг в Instagram.** Трек из библиотеки
Instagram через API не прикрепляется — это ограничение платформы
(`docs/instagram_reels_daily.md` §3.3), а без музыки охваты заметно ниже.
Поэтому последний шаг ручной: Мария получает готовое видео и тексты, в самом
Instagram накладывает трек и публикует — около двадцати секунд работы.
Побочно снимается и §3.5: Telegram принимает файл прямой загрузкой, публичный
URL для MP4 не нужен.

## Модули

| Файл | Назначение |
|---|---|
| `pipeline.js` | оркестратор: соединяет шаги, не знает про env и диск |
| `bin/run.js` | точка входа для слота расписания: окружение, состояние, запуск |
| `niches.js` | 9 тематик из ТЗ и поисковые запросы под каждую |
| `trends.js` | отсев чужеязычных, ранжирование и дедупликация, **не знает про источник** |
| `sources/youtube.js` | источник трендов на YouTube Data API v3 |
| `sources/drive.js` | подложки и базы знаний из Google Drive |
| `generate.js` | заголовок, надпись на видео, пост, перевод |
| `render.js` | клиент к `services/video-worker`: надпись поверх подложки |
| `delivery/telegram.js` | доставка готового рилса в бота |
| `bin/probe.js` | живая проверка: печатает хуки, которые источник отдаёт сейчас |
| `bin/tg-chat-id.js` | показывает `TELEGRAM_CHAT_ID` для доставки |

## Контракт источника

Источник — объект с методом `fetchCandidates()`, возвращающий
`{ candidates, errors }`. Кандидат единого формата:

```js
{
  id: "abc123",
  source: "youtube",
  title: "I Quit My Job After This",
  url: "https://www.youtube.com/shorts/abc123",
  niche: "ai_income",
  views: 84000,
  publishedAt: "2026-09-21T10:00:00Z",
  channel: "Some Channel",
}
```

Отбор (`trends.js`) работает только с этим форматом, поэтому источник сменный:
чтобы перейти на другой сервис, достаточно добавить файл в `sources/` с тем же
контрактом — ранжирование, дедупликация и всё, что ниже по пайплайну, не меняется.

## Как отбирается хук

**Ранжирование — по скорости, а не по сырым просмотрам.** В окне 24 часа
ролик, вышедший час назад с 50 000 просмотров, вируснее вчерашнего с 100 000.
Метрика — просмотры в час; возраст снизу поджат одним часом, иначе свежий
ролик давал бы бесконечную скорость.

**Дедупликация — по смыслу, а не по строке.** Вирусный хук расходится по
авторам с мелкими правками: «I Quit My Job After This» и «She Quit Her Job
After This» — один и тот же заголовок. Сравниваются доли общих значимых слов
(мера Жаккара), порог 0.6. Проверка идёт и против истории публикаций за
последние дни, и внутри текущей выборки.

**Язык — отдельным фильтром, до ранжирования.** `regionCode=US` и
`relevanceLanguage=en` у источника — подсказки ранжирования, а не фильтр:
в выдаче по английскому запросу регулярно оказываются хинди, японский и
арабский. Для англоязычной ленты такой хук бесполезен, поэтому заголовок
проверяется на долю латинских букв (порог 0.8). Хэштеги при этом
выбрасываются: они латинские независимо от языка ролика, и гроздь
`#HealthTips #YouTubeShorts #Shorts` иначе перевешивает короткий заголовок
на хинди.

Порядок важен: сначала ранжирование, потом дедупликация — тогда из группы
похожих заголовков остаётся самый вирусный, а не случайный.

## Доставка в Telegram

Бот не пишет первым и не знает получателя по ссылке — нужен `TELEGRAM_CHAT_ID`.
Напишите боту любое сообщение, затем:

```bash
TELEGRAM_BOT_TOKEN=... node bin/tg-chat-id.js
```

Скрипт напечатает готовую строку `TELEGRAM_CHAT_ID=...`. Для канала добавьте
бота администратором — его id будет отрицательным.

Приходит три сообщения: видео со сводкой (что за хук, предупреждения проверок),
подпись для Instagram на английском и исходный русский пост. Тексты отдельно,
потому что подпись к видео в Telegram ограничена 1024 символами, а пост по
инструкции — 1700–1900.

**Токен равен полному доступу к боту.** Только переменная окружения; если он
где-то засветился — `@BotFather` → `/mybots` → бот → *API Token* → *Revoke*.

С российского сервера `api.telegram.org` заблокирован; в `docker-compose.yml`
он уже проксируется прозрачно (`tg-proxy-forward` + `extra_hosts`), поэтому
в коде обычный адрес и настраивать ничего не нужно.

## Что нужно, чтобы запустить целиком

| Переменная | Откуда |
|---|---|
| `YOUTUBE_API_KEY` | Google Cloud Console → YouTube Data API v3 |
| `GOOGLE_ACCESS_TOKEN` | OAuth с `drive.readonly`; живёт час, обновляется перед слотом |
| `TELEGRAM_BOT_TOKEN` | @BotFather |
| `TELEGRAM_CHAT_ID` | `bin/tg-chat-id.js` |
| `VIDEO_RENDER_URL`, `VIDEO_RENDER_TOKEN` | `services/video-worker` |

Плюс живые блокеры из ТЗ: в папке подложек нужны файлы (§3.2), а в папке
«инструкции» — базы знаний копирайтера и переводчика (§3.4). Без них пайплайн
падает на соответствующем шаге, а не публикует «общий» текст.

Состояние между запусками (история хуков за 30 дней и занятые подложки) лежит
в `.state.json` рядом с сервисом; путь переопределяется через `STATE_FILE`.
Файл в git не попадает.

## Ключ YouTube API

Ключ читается из `YOUTUBE_API_KEY`. **В репозиторий его класть нельзя.**

- локально и на сервере — переменная окружения (`.env`, docker-compose);
- для облачной сессии Claude Code — поле `Environment variables` в настройках
  окружения, или `API credentials` на планах Pro/Max, где ключ не виден агенту.

Получить: Google Cloud Console → включить *YouTube Data API v3* → создать
API key. Ключ стоит ограничить этим одним API.

### Квота

Дневной лимит по умолчанию — 10 000 единиц. `search.list` стоит 100, `videos.list` — 1.
Девять ниш по три запроса, дважды в сутки — примерно 5 400 единиц. Запас есть,
но добавлять запросы в `niches.js` без пересчёта не стоит.

## Проверка

```bash
node --test test/*.test.js               # 82 теста, без сети

YOUTUBE_API_KEY=... node bin/probe.js    # живая выдача, ничего не публикует
YOUTUBE_API_KEY=... node bin/probe.js --niches money,ai_income --limit 5

node bin/run.js                          # полный проход: один рилс в Telegram
node bin/run.js --niches money,ai_income
```

`probe.js` только читает и печатает — безопасно запускать сколько угодно,
единственная цена это квота.
